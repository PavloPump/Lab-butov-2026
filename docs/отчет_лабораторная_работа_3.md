## 1. Краткое описание интерфейсного решения

Разработан пользовательский интерфейс системы управления доставкой грузов с учётом потребностей трёх групп пользователей: клиентов, водителей и администраторов. Интерфейс выполнен в современном минималистичном стиле с использованием цветовой схемы на основе индиго и серых тонов, что обеспечивает приятный визуальный опыт и хорошую читаемость.

**Основные принципы дизайна:**
- **Минимализм:** Чистый интерфейс без лишних элементов, фокус на контенте
- **Консистентность:** Единый стиль компонентов, цветов и типографики на всех экранах
- **Отзывчивость:** Адаптивный дизайн для работы на различных устройствах
- **Интуитивность:** Понятная навигация и логичное расположение элементов
- **Доступность:** Чёткие контрасты, читаемые шрифты, понятные подписи

**Цветовая палитра:**
- Основной цвет: индиго (#667eea) — для акцентных элементов и кнопок
- Фон: градиент от светло-голубого к индиго для главной страницы
- Карточки: белый (#ffffff) с лёгкими тенями
- Статусы: цветовая кодировка (жёлтый — ожидает, синий — в процессе, зелёный — доставлен)

**Типографика:**
- Заголовки: крупный жирный шрифт для иерархии
- Текст: средний размер для основного контента
- Мелкий текст: для подписей и статусов

## 2. Пользовательские сценарии

### Сценарий 1: Регистрация нового пользователя (клиент)

**Шаги:**
1. Пользователь открывает главную страницу приложения
2. Нажимает кнопку "Регистрация" в навигационной панели
3. Переходит на страницу регистрации
4. Заполняет форму:
   - Имя
   - Email
   - Телефон
   - Пароль
   - Выбирает роль "Клиент"
5. Нажимает кнопку "Зарегистрироваться"
6. После успешной регистрации перенаправляется на панель клиента

**Реализованные элементы:**
- Главная страница с призывом к действию
- Форма регистрации с валидацией полей
- Выбор роли пользователя
- Навигация между страницами

### Сценарий 2: Авторизация и работа клиента

**Шаги:**
1. Пользователь открывает главную страницу
2. Нажимает кнопку "Войти"
3. Заполняет форму авторизации (email, пароль)
4. Нажимает кнопку "Войти"
5. Перенаправляется на панель клиента
6. Просматривает список своих заказов со статусами
7. При необходимости создаёт новый заказ

**Реализованные элементы:**
- Форма авторизации
- Панель клиента с двумя секциями:
  - Создание нового заказа
  - Список заказов со статусами
- Карточки заказов с цветовой индикацией статуса

### Сценарий 3: Авторизация и работа водителя

**Шаги:**
1. Водитель открывает главную страницу
2. Нажимает кнопку "Войти"
3. Заполняет форму авторизации
4. Перенаправляется на панель водителя
5. Просматривает список доступных заказов
6. Принимает заказ нажатием кнопки
7. Управляет текущими доставками (обновляет статус)

**Реализованные элементы:**
- Панель водителя с двумя секциями:
  - Доступные заказы с деталями (вес, габариты)
  - Текущие доставки с возможностью обновления статуса
- Кнопки действий для каждого заказа

## 3. Описание макета

**Назначение макета:** Интерактивный прототип пользовательского интерфейса, демонстрирующий основные экраны и пользовательские сценарии системы управления доставкой грузов. Макет служит основой для реализации фронтенд-части приложения и позволяет визуализировать пользовательский опыт до начала разработки.

**Технология реализации:** HTML/CSS/JavaScript прототип без использования фреймворков. Это позволяет быстро создать интерактивный макет, который можно открыть в любом браузере без дополнительной настройки.

**Ссылка на макет:** [Открыть интерактивный прототип](../prototype/index.html)

Для просмотра макета откройте файл `docs/prototype/index.html` в браузере.

**Реализованные экраны:**

1. **Главная страница (Home)**
   - Лендинг с описанием системы
   - Три карточки с описанием возможностей для разных ролей
   - Кнопки "Начать сейчас" и "Войти в систему"
   - Навигационная панель с логотипом и ссылками

2. **Страница входа (Login)**
   - Форма авторизации с полями email и пароль
   - Кнопка входа
   - Ссылка на регистрацию
   - Ссылка возврата на главную страницу
   - Центрированная карточка на градиентном фоне

3. **Страница регистрации (Register)**
   - Форма регистрации с полями:
     - Имя
     - Email
     - Телефон
     - Пароль
     - Выбор роли (Клиент/Водитель)
   - Кнопка регистрации
   - Ссылка на вход для существующих пользователей
   - Валидация обязательных полей

4. **Панель клиента (Client Dashboard)**
   - Заголовок "Панель клиента"
   - Секция "Создать новый заказ" с кнопкой
   - Секция "Мои заказы" со списком заказов
   - Карточки заказов с:
     - Номером заказа
     - Маршрутом (откуда → куда)
     - Статусом с цветовой индикацией
   - Навигационная панель с индикацией роли

5. **Панель водителя (Driver Dashboard)**
   - Заголовок "Панель водителя"
   - Секция "Доступные заказы" со списком:
     - Номер заказа
     - Маршрут
     - Вес и габариты груза
     - Кнопка "Принять заказ"
   - Секция "Текущие доставки" со списком:
     - Номер заказа
     - Маршрут
     - Статус
     - Кнопка "Обновить статус"
   - Навигационная панель с индикацией роли

**Интерактивность:**
- Навигация между экранами через JavaScript
- Кнопки с hover-эффектами
- Адаптивный дизайн для мобильных устройств
- Плавные переходы между состояниями

**Пользовательские сценарии, отражённые в макете:**
- **Сценарий 1:** Новый пользователь → Главная страница → Регистрация → Выбор роли → Создание аккаунта
- **Сценарий 2:** Существующий клиент → Главная страница → Вход → Панель клиента → Создание заказа → Просмотр статусов
- **Сценарий 3:** Существующий водитель → Главная страница → Вход → Панель водителя → Просмотр доступных заказов → Принятие заказа → Управление доставкой

## 4. Описание реализованной части приложения

В рамках лабораторной работы реализован начальный этап фронтенд-приложения с соблюдением архитектурных принципов, определённых в лабораторной работе №2.

### Реализованные компоненты

**Layout компонент (`frontend/src/components/Layout.tsx`)**
- Переиспользуемый компонент обёртки для всех страниц
- Навигационная панель с логотипом и ссылками
- Адаптивная индикация роли пользователя
- Параметры:
  - `showNav` — отображение навигации
  - `userRole` — роль пользователя (CLIENT/DRIVER/ADMIN/null)

**Button компонент (`frontend/src/components/Button.tsx`)**
- Переиспользуемый компонент кнопки
- Варианты: primary (индиго), secondary (белый с рамкой)
- Поддержка типов button и submit
- Кастомные className

**Input компонент (`frontend/src/components/Input.tsx`)**
- Переиспользуемый компонент поля ввода
- Поддержка типов: text, email, password, tel
- Автоматическая обёртка с label
- Обязательные поля

### Обновлённые страницы

**HomePage**
- Интегрирован Layout компонент
- Сохранён оригинальный дизайн из макета
- Навигация через React Router

**LoginPage**
- Интегрирован Layout компонент
- Используются Input и Button компоненты
- Сохранён оригинальный дизайн

**RegisterPage**
- Интегрирован Layout компонент
- Используются Input и Button компоненты

- Сохранён оригинальный дизайн

**ClientDashboard**
- Интегрирован Layout компонент с userRole="CLIENT"
- Улучшен дизайн с grid layout
- Добавлены карточки заказов с цветовой индикацией статуса
- Кнопки действий

**DriverDashboard**
- Интегрирован Layout компонент с userRole="DRIVER"
- Улучшен дизайн с grid layout

### Подключение архитектурных слоёв

**API сервис (`frontend/src/services/api.ts`)**

**Конфигурация окружения**
- Создан `.env.example` с примером конфигурации
- `VITE_API_URL` для указания URL backend API

### Соответие архитектуре

Реализованная часть приложения соответствует Clean Architecture, определённой в лабораторной работе №2:

- **Presentation Layer:** React компоненты (Layout, Button, Input) и страницы
- **Application Layer:** API сервис для связи с backend
- **Domain Layer:** Типы данных (будут добавлены при полной реализации)
- **Infrastructure Layer:** HTTP клиент (fetch API)

Структура проекта соответствует архитектуре:
```
frontend/src/
├── components/     # Переиспользуемые UI компоненты
├── pages/          # Страницы приложения
├── services/       # API сервисы

├── hooks/          # Custom hooks (будут добавлены)
├── contexts/       # React Context (будет добавлен)
```
