### Архитектурные принципы

Реализованная часть приложения следует принципам Clean Architecture:

**Разделение слоёв:**
- **Presentation Layer:** Компоненты UI (components, pages)
- **Business Logic Layer:** Custom hooks (hooks)
- **Data Layer:** Сервисы данных (services)
- Чёткое разделение ответственности

**Переиспользуемые компоненты:**
- Layout, Button, Input — базовые UI компоненты
- Alert, EmptyState, LoadingSpinner — компоненты для состояний
- Все компоненты переиспользуемы и типизированы

**Custom hooks:**
- useAuth — изоляция логики авторизации
- useOrders — изоляция логики заказов
- useDriver — изоляция логики доставок
- Переиспользуемая бизнес-логика

**Context API:**
- AuthContext для глобального состояния авторизации
- Избегание prop drilling
- Централизованное управление состоянием

**TypeScript:**
- Строгая типизация всех компонентов
- Интерфейсы для данных (User, Order, Delivery)
- Типизированные пропсы компонентов
- Типизированные ответы API
