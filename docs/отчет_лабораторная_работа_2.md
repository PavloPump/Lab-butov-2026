## 1. Требования к приложению

**Тема работы:** Разработка веб-приложения для управления процессом доставки грузов с функционалом для клиентов и водителей.

### Функциональные требования

**Для клиентов:**
- Регистрация и авторизация в системе
- Создание заказов на доставку грузов с указанием:
  - Адреса pickup (забора груза)
  - Адреса доставки
  - Описания груза
  - Веса и габаритов груза
  - Желаемого времени доставки
- Просмотр списка своих заказов
- Отслеживание статуса заказа в реальном времени
- Просмотр информации о назначенном водителе

**Для водителей:**
- Регистрация и авторизация в системе
- Просмотр списка доступных заказов
- Принятие заказов на выполнение
- Обновление статуса доставки
- Обновление текущего местоположения
- Просмотр истории выполненных доставок

**Для администраторов:**
- Управление пользователями (клиенты, водители)
- Управление заказами
- Просмотр статистики и аналитики
- Мониторинг системы

### Нефункциональные требования

- **Производительность:** Время отклика API не более 200 мс
- **Безопасность:** Хеширование паролей, JWT аутентификация, HTTPS
- **Масштабируемость:** Архитектура должна поддерживать горизонтальное масштабирование
- **Надёжность:** 99.9% uptime, автоматическое резервное копирование данных
- **Доступность:** Веб-интерфейс, адаптивный дизайн для мобильных устройств

### Технические требования

- Поддержка современных браузеров (Chrome, Firefox, Safari, Edge)
- Поддержка мобильных устройств (iOS, Android)
- Работа в реальном времени (WebSocket для отслеживания)
- Интеграция с картографическими сервисами (в будущем)

## 3. Архитектура приложения

### 3.1 Архитектурный подход

Выбран **Clean Architecture (Layered Architecture)** — паттерн, который обеспечивает разделение ответственности и независимость слоёв приложения.

**Преимущества выбранного подхода:**
- Разделение ответственности — каждый слой имеет чёткую задачу
- Тестируемость — бизнес-логика изолирована от инфраструктуры
- Масштабируемость — слои можно развивать независимо
- Поддерживаемость — изменения в одном слое не влияют на другие
- Переиспользуемость — бизнес-логика может использоваться разными интерфейсами

### 3.2 Логическое разбиение на слои

#### Слой 1: Presentation Layer (Слой представления)

**Ответственность:** Обработка HTTP запросов, маршрутизация, middleware, валидация входных данных, формирование HTTP ответов.

**Компоненты:**
- Express маршруты (`/routes`) — определение API endpoints
- Middleware (`/middleware`) — обработка ошибок, аутентификация, логирование
- Контроллеры (в будущем) — связывание routes с services

**Взаимодействие:** Принимает HTTP запросы, вызывает Application Layer, возвращает HTTP ответы.

#### Слой 2: Application Layer (Слой приложения)

**Ответственность:** Бизнес-логика, use cases, оркестрация работы между слоями, преобразование данных.

**Компоненты:**
- Сервисы (`/services`) — UserService, OrderService, DeliveryService
- DTO (Data Transfer Objects) (`/dto`) — объекты для передачи данных между слоями

**Взаимодействие:** Использует Domain Layer для бизнес-операций, вызывает Infrastructure Layer для сохранения данных.

#### Слой 3: Domain Layer (Слой домена)

**Ответственность:** Сущности и бизнес-правила, полностью независим от инфраструктуры и внешних систем.

**Компоненты:**
- Сущности (`/entities`) — User, Order, Delivery
- Интерфейсы репозиториев (`/repositories`) — IUserRepository, IOrderRepository, IDeliveryRepository

**Взаимодействие:** Определяет структуру данных и бизнес-правила, не зависит от других слоёв.

#### Слой 4: Infrastructure Layer (Слой инфраструктуры)

**Ответственность:** Работа с внешними системами, база данных, внешние API.

**Компоненты:**
- Реализации репозиториев (`/repositories`) — UserRepository, OrderRepository, DeliveryRepository
- Конфигурация базы данных (`/database`) — Prisma client

**Взаимодействие:** Реализует интерфейсы из Domain Layer, обеспечивает сохранение и извлечение данных.

### 4.4 Обеспечение сборки и запуска проекта

**Скрипты в package.json:**

```json
{
  "scripts": {
    "dev": "concurrently \"npm run dev:backend\" \"npm run dev:frontend\"",
    "dev:backend": "npm run dev --workspace=backend",
    "dev:frontend": "npm run dev --workspace=frontend",
    "build": "npm run build --workspaces",
    "build:backend": "npm run build --workspace=backend",
    "build:frontend": "npm run build --workspace=frontend",
    "test": "npm run test --workspaces",
    "lint": "npm run lint --workspaces"
  }
}
```

**Backend скрипты:**
- `npm run dev` — Запуск с ts-node-dev (hot reload)
- `npm run build` — Компиляция TypeScript
- `npm start` — Запуск скомпилированного приложения
- `npm run prisma:generate` — Генерация Prisma Client
- `npm run prisma:migrate` — Выполнение миграций

**Frontend скрипты:**
- `npm run dev` — Запуск Vite dev server (порт 5173)
- `npm run build` — Сборка для production
- `npm run preview` — Предпросмотр production build

**Запуск проекта:**
1. Установка зависимостей: `npm install`
2. Настройка .env файла в backend
3. Генерация Prisma Client и миграции
4. Запуск: `npm run dev` (запускает backend и frontend одновременно)
